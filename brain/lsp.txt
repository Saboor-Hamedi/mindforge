LANGUAGE SERVERS (LSP) & COMPLETION
===================================

MindForge's Vim mode embeds Neovim, so it uses Neovim's built-in LSP client.
You get a VS Code style completion dropdown, snippets (the HTML skeleton,
React hooks, Python def, ...), hover documentation, symbol renaming, code actions,
diagnostics, and go-to-definition. Servers are installed and configured from Lua,
the same way you would in Neovim.

Note: LSP currently works in Vim mode only. Hybrid mode and the Markdown
editor do not run language servers yet.


1. QUICK START
--------------
Open a file (Ctrl+O or :open) or name a note with an extension (app.jsx,
index.html, main.py), switch to Vim mode, then run:

    :LspInstall          install the servers for the current file type
    :LspInstall html css ts_ls     install specific servers

Installs run in the background; progress is shown in the message line.
Snippet completion works immediately, with no server installed. Type "def" in a
.py file or "html" in an .html file and press Tab/Enter to expand.


2. LANGUAGE INTELLIGENCE KEYMAPS
--------------------------------
    K                  Hover documentation popup (:Hover) - Esc immediately closes it
    gd                 Go to definition (:Definition)
    gr                 Find references (:References)
    <F2>               Symbol rename (:Rename) - notifies if unsupported
    <leader>rn         Symbol rename (Space + r + n)
    Alt+Enter (<M-CR>) Code action / Quick-fix (:CodeAction)
    <leader>ca         Code action (Space + c + a)
    Alt+Shift+F (<A-F>) Format document (:Format)
    <leader>f          Format document (Space + f)
    <leader>d          Show line diagnostic floating message
    [d / ]d            Jump to previous / next diagnostic


3. KEYS IN THE COMPLETION DROPDOWN & SNIPPETS
---------------------------------------------
    Enter              Accept top suggestion or selected item immediately (e.g. h1 -> <h1></h1>)
    Ctrl+J             Next completion item (does NOT toggle terminal while open)
    Ctrl+K             Previous completion item
    Tab                Accept item or trigger completion
    Shift+Tab          Previous item in menu / previous snippet placeholder
    Esc                Close completion dropdown / close hover floating window / cancel snippet
    Ctrl+Space         Open completion dropdown manually
    Ctrl+L             Return focus from the sidebar/right pane to the editor
    Ctrl+H             Remains editor input (Hybrid backspace; forwarded to Neovim in Vim mode)

Snippet Placeholders (VS Code Friendly):
    - Expanding snippets (e.g. "def", "fn", "html5") highlights placeholders
      with an elegant accent underline.
    - Press Tab / Shift+Tab to jump between placeholders.
    - Pressing Esc, switching modes, or leaving the buffer immediately stops
      the snippet session and clears all placeholder marks.
    - Reaching the final placeholder ($0) and pressing Tab or Enter cleanly
      completes the snippet with zero lingering highlights.


4. MOUSE SELECTION & DRAG
-------------------------
    Left Click         Move cursor to clicked cell
    Left Drag          Smoothly select text; selection background tracks mouse live
    Double-Click       Select word under cursor
    Triple-Click       Select whole line under cursor
    Esc in Normal      Clears search highlights (:nohlsearch) and active snippets


5. COMMANDS
-----------
    :LspInstall [names]    Install servers (default: servers for active file type)
    :LspUninstall names    Remove a managed server
    :LspList               Browse installed and available language servers
    :LspInfo               Show servers attached to the current buffer
    :LspRestart            Restart language servers for the current buffer
    :LspConfig             Open your lsp.lua configuration
    :Format                Format current buffer using active LSP server
    :Rename                Rename symbol under cursor
    :CodeAction            Trigger LSP quick-fixes and refactorings
    :References            Find all references to symbol under cursor
    :Hover                 Show hover documentation for symbol
    :Definition            Jump to symbol definition


6. BUILT-IN SERVERS
-------------------
    html, cssls, jsonls    vscode-langservers-extracted (npm)
    ts_ls                  JavaScript / TypeScript / JSX / TSX (npm)
    emmet_ls               Emmet abbreviations (npm)
    pyright                Python (npm)
    yamlls                 YAML (npm)
    intelephense           PHP (npm)
    rust_analyzer          Rust (rustup component add rust-analyzer)

npm servers are installed into:   <home>\nvim\servers\npm
A server already on your PATH is used as-is. npm (Node.js) and rustup must be
installed for the respective servers.
<home> = %APPDATA%\mindforge\mindforge


7. CUSTOMISING WITH LUA
-----------------------
First launch creates   <home>\nvim\lsp.lua   (never overwritten). Edit it:

    return {
      disable = { 'emmet_ls' },        -- do not run these
      hints = false,                   -- silence "run :LspInstall" hints
      servers = {
        -- override settings of a built-in server
        pyright = { settings = { python = { analysis = { typeCheckingMode = 'basic' } } } },

        -- add any language you like
        lua_ls = {
          cmd = { 'lua-language-server' },
          filetypes = { 'lua' },
          root_markers = { '.luarc.json', '.git' },
        },
      },
    }

Entries are merged over the built-in ones, so you only list what changes.
A custom server only needs cmd, filetypes and root_markers.


8. BRING YOUR OWN CONFIG (NATIVE NEOVIM STYLE)
----------------------------------------------
Any file   <home>\nvim\lsp\<name>.lua   returning a config table is loaded as
a native Neovim 0.11 server definition and enabled automatically:

    -- <home>\nvim\lsp\gopls.lua
    return {
      cmd = { 'gopls' },
      filetypes = { 'go', 'gomod' },
      root_markers = { 'go.mod', '.git' },
    }

Your own <home>\nvim\init.lua still loads as before and can call
vim.lsp.config() / vim.lsp.enable() directly.


9. ADDING A SERVER TO THE CATALOGUE
-----------------------------------
Built-in definitions live in app/assets/nvim/mindforge/lsp/registry.lua. Each
entry has desc, npm (package list) or rustup (component), bin and config.


10. TROUBLESHOOTING
-------------------
- No dropdown: run :LspInfo. Snippets always show; semantic items need a
  server from :LspList.
- "npm not found": install Node.js and restart MindForge.
- Server fails to start: run it by hand (<home>\nvim\servers\npm\node_modules\.bin).
- Hover documentation: Press K or run :Hover over any identifier.

Built-in HTML / JSX / TSX completion
  No server needed: type a tag (h1) or an Emmet abbreviation (ul.menu>li*3, div#app.card)
  and accept with Tab/Enter to expand it. In .html files type ! for the HTML5 skeleton.
  In JSX/TSX class becomes className and void tags are self-closed.

:LspList panel
  :LspList [filter] opens a scrollable list of every server (installed first).
  Type to filter, Up/Down/Ctrl+J/K move, Enter installs, Del uninstalls, Esc closes.
  Completion popup: arrows, Ctrl+J/K, Tab/Enter accept, mouse hover and click.
  ts_ls needs TypeScript 5: run :LspInstall ts_ls once.

eslint: starts only in a project with an ESLint config AND node_modules/eslint installed (npm i -D eslint); otherwise it stays off.

STATUS BAR INDICATOR
  Left of the language label in the status bar: filled dot = server connected, hollow dot = starting, x = server not installed (hover for names). No dot = no LSP for this language (e.g. markdown).

INFO / LOG
  :LspInfo  attached servers with their project root.
  :LspLog   opens the language server log file.
